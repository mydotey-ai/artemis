# 文档规则

## 目录结构

文档统一放置在 `/docs/` 目录下，按类型分目录。项目尚无 `/docs/` 时，首次需要写文档则按此结构创建所需目录，不预建空目录。

| 目录 | 用途 |
| ------ | ------ |
| `arch/` | 架构设计文档 |
| `api/` | API 接口文档 |
| `data/` | 数据设计文档 |
| `ui/` | UI 设计文档 |
| `dev/` | 开发文档 |
| `deploy/` | 部署文档 |
| `decisions/` | 架构决策记录 (ADR)，一决策一文件：`adr-<序号>-<名称>.md`，如 `adr-001-use-redis.md` |
| `issues/` | 问题记录文档 |
| `milestones/` | 里程碑规划：每个里程碑一个 `v-xxx/` 子目录，内含规划文档和 `phases/`（阶段实施文档，命名 `phase-X-xxx.md`） |
| `plans/` | 临时开发计划，完成后保留；目录加入 `.gitignore`，不入库 |
| `product/` | 产品文档 |

## 索引文件

每个目录（含 `/docs/` 根）以 `README.md` 作为索引，只登记直接子项，不递归展开。文档新增、删除、移动时同步更新所在目录索引。

## 文档头与更新历史

- 除索引文件外，文档标题下首行标注版本与更新时间：

  ```
  版本: 1.0    更新时间: YYYY-MM-DD
  ```

- 文档末尾设「更新历史」小节，一版一行，最新版本在前：

  | 版本 | 日期 | 变更说明 |
  | ------ | ------ | ------ |
  | 1.1 | YYYY-MM-DD | 本次变更 |
  | 1.0 | YYYY-MM-DD | 初版 |

- 每次修改文档同步更新版本号、更新时间与更新历史。
- 索引文件（`README.md`）例外：
  - 索引自身不标版本与更新时间，也不设更新历史。
  - 索引登记被索引文档时同样不写版本与更新时间，只登记文档、状态与说明——版本与时间以文档自身头部为准，不在索引中重复。

## 文档格式

- Markdown 格式，文件名 `kebab-case`，文件名和索引中不带日期、版本等元信息
- 每个文档以一级标题开头，简要说明文档目的
- 章节标题按二级、三级递进，不跳级
- 代码块标注语言类型（`java`、`sql`、`bash` 等）
- 表格用于结构化数据（配置项、API 参数、状态对比等）

## 文档更新机制

任何变更发生后，同步更新所有受影响的文档，不限于下列常见场景：

- **新增功能**：更新对应类型文档
- **Phase 完成**：更新 Phase 文档
- **架构变更**：更新相关架构文档，重大决策在 `decisions/` 下新增 ADR 文件
- **API 变更**：更新 `/docs/api/` 下对应文档
