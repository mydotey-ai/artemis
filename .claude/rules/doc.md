# 文档规范

## 目录结构

```
docs/
├── README.md                  # 文档索引（唯一索引文件）
├── legacy-product-analysis.md # 原产品能力基线（重设计需求输入）
├── adr/                       # 架构决策记录
│   └── NNNN-kebab-case.md
└── design/                    # 主题设计文档
    └── <topic>.md
```

- 基线/规范类文档放 `docs/` 根；具体决策进 `adr/`，具体方案进 `design/`。

## 命名

- 文件名小写 kebab-case 英文；ADR 前缀四位递增编号（`0001-`）。
- 正文中文；技术名词、代码标识符、文件路径保留英文原文。

## 文档头

每份文档标题下首行标注元信息：

```
状态: 草案 | 评审中 | 定稿 | 已废弃    日期: YYYY-MM-DD
```

## 文档索引

- `docs/README.md` 是唯一索引文件，表格三列：文档 | 状态 | 说明。
- 新建文档当次登记；状态变更同步更新。

## ADR

- 一页纸，四段：背景 / 决策 / 后果 / 与基线的关系。
- **只增不改**：决策变更写新 ADR，旧 ADR 标记「已废弃（被 ADR-NNNN 取代）」。

## 设计文档

- 按主题一份，不按日期建版本。
- 必须包含：「目标 / 非目标」+ 与 `docs/legacy-product-analysis.md` §5 资产、§6 局限的对照。
- 文档随代码更新，冲突当次提交修齐。

## 证据引用

- 本仓库代码：相对仓库根路径。
- 原产品代码：相对原仓库（`~/Projects/mydotey/artemis`）根路径，并注明「原仓库」。
- 不可证实的结论标注「待验证」；原产品能力结论直接引用基线文档，不重复调查。
- 过时文档标记废弃而非删除。
