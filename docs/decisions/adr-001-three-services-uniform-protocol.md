# ADR-001：三服务拆分 + 统一网络协议（all-in-one 也是）

版本: 1.0    更新时间: 2026-10-10

## 状态

Accepted（2026-10-10，架构设计定稿）

## 背景

原产品单进程承载注册发现与治理全部职责。重设计需要：registry（数据面写路径）、discovery（读扩展与多集群聚合）、management（治理面 + DB）三者的负载特征与扩缩节奏不同；且需提供从单机 eval 到 K8s 独立编排的多种部署形态。

## 决策

产品拆为 registry / discovery / management 三个可独立部署的服务，同一代码库三种装配形态；三服务之间（含 all-in-one 形态内部）一律走网络协议（gRPC）通信，不做进程内直连优化。

## 理由

- 独立扩缩、故障隔离、多集群聚合（discovery 订阅 1..N 个 registry 集群）。
- 一种通信语义无特例：all-in-one 与分拆部署行为一致，测试与排障模型单一。

## 否决方案

进程内直连优化 all-in-one——引入两套通信语义，行为分叉。

## 后果

- 内部通信有序列化开销（可接受，换取语义统一）。
- 部署形态（Docker 单机 / VM / K8s）只是装配差异（架构 §2.3）。
