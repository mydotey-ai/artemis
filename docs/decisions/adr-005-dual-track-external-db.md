# ADR-005：双轨 + 外部 DB（治理元数据）

版本: 1.0    更新时间: 2026-10-10

## 状态

Accepted（2026-10-10，架构设计定稿）

## 背景

原产品数据面（注册表纯内存）与管理面（DB 持久化流量治理元数据）双轨分离，为组件层结构实践（能力基线 §2.5/§2.7）。治理规则是持久数据，版本管理合理；注册数据是临时数据（ADR-003 不搞版本）。

## 决策

数据面保持纯内存 AP；治理元数据入外部 DB（MySQL/PG 双方言，期 3 management 交付）。management 可不部署——registry + discovery 独立可用。

## 理由

- 原产品血统延续（双轨实践被 10 万级验证）。
- Java/Rust 互通面最小化（Rust 只做数据面，无 DB/治理面）。
- 治理面实现简单（规则即数据，可版本化 + ack 闭环）。

## 否决方案

- 内嵌 Raft 分层：工程量大、混合集群互通难。
- 全 AP（治理规则也无版本）：规则竞态。

## 后果

- 单机 eval 零 DB 依赖（management 后置部署）。
- 治理规则走「版本 + ack 生效闭环」（架构 §5.2），与数据面零版本决策对照。
