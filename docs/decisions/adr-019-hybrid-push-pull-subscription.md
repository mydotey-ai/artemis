# ADR-019：订阅推送推拉结合（增量流 + 全量拉兜底 + hash 对账）

版本: 1.1    更新时间: 2026-10-23

## 状态

Accepted（2026-10-23，v0.3 phase-3 设计 review 定案；取代 [ADR-007](adr-007-snapshot-push-unit.md) 的订阅通道推送形态部分）

## 背景

ADR-007 定订阅推送单元 = service 实例集快照（原子、幂等覆盖），否决实例级 delta。v0.3 phase-3 设计 review 中裁决修订：稳态快照推送带宽 = O(服务实例数 × 变更频率)，大服务 × 多订阅方场景下放大明显（10 万实例目标），改推拉结合。原产品增量推送的真实教训不在「增量」本身，而在**无版本/世代导致丢失不可检测**（局限 #3：delta 机制设计而未用、漏推最久 15min 才纠正）——以 hash 对账补上显式丢失检测，即可安全使用增量。

## 决策

discovery → SDK 订阅通道为推拉结合三件套：

1. **实时推增量**：`Subscribe`（server-stream）推**视图语义变更批**——首条空批为建立确认，随后逐 service 推命中基线（全 NEW 批），稳态推增量变更（labels 订阅由服务端翻译为视图语义：实例匹配态翻转转 NEW/DELETE，SDK 无脑 apply）；一流多目标、单流内按产生序有序。
2. **定期拉全量**：Query（既有 unary 查询）+ SDK 三层兜底轮询（推送失败/空服务 60s 主动拉、15min 全量刷新，资产 #8）。
3. **hash 对账**：服务端暴露 per-service 视图 checksum（随投影条目缓存维护，响应即读缓存零计算）；SDK 定期拉 checksum 表与本地逐 service 比对，不一致的 service 触发全量拉——增量丢失的**显式检测**，漂移窗口 = 对账周期。

配套语义：

- **快照语义保留于拉取面**：投影、查询、首推基线、对账单元仍 = service 实例集快照（ADR-007 单元定义继续成立）。
- **上游重连覆盖 = diff 续推增量，订阅流与上游状态解耦**：discovery 重连 registry 重新 bootstrap 时，覆盖前取旧投影、与新快照 diff 生成变更批（服务消失全 DELETE / 新建全 NEW / 实例增删改），经与稳态增量完全相同的翻译扇出路径推送（旧值取覆盖前投影）——SDK 流不断，断连期间投影冻结、流静默（陈旧换可用，与查询一致），重连后 diff 收敛。SDK 流生命周期只由 SDK↔discovery 连接与慢消费者决定，registry↔discovery 抖动对订阅方透明（上游降级感知归新鲜度标记）。
- **慢消费者断流**（isReady 背压）与 at-most-once 投递哲学不变（同 ADR-018）。

## 理由

- 稳态带宽 O(变更数) 而非 O(服务实例数 × 变更数)；
- 丢失检测显式且轻量：checksum 表（每 service 一个 4 字节级指纹）远小于全量数据，比对纯客户端侧 diff，服务端无 per-subscriber 状态；
- SDK 复杂度由服务端视图语义翻译压到最低（收到即 apply，无需自行判断 labels 匹配态）；
- 对标 Nacos 2.x（gRPC 推全量 ServiceInfo 快照）在千兆内网可行，但 10 万实例目标 + 治理差异化（分组订阅）下，增量 + 对账的带宽与确定性更优。

## 否决方案

- **纯快照推送**（ADR-007 原案）：稳态带宽放大；丢失自愈依赖「下次任意变更覆盖」或 15min 兜底，窗口不可控。
- **增量 + 版本号/世代**（原产品 services-delta 路径）：需要 per-subscriber 推送水位跟踪 + 版本间隙 delta 拉取 API，服务端有状态、复杂度高于 checksum 对账。
- **覆盖后断全部订阅流重订阅**：免 diff 逻辑，但 registry↔discovery 抖动（重连、registry 重启）传染为全部 SDK 订阅闪断与集中重订阅，破坏订阅流与上游状态的解耦。

## 后果

- ADR-007 状态改 Superseded（订阅通道推送形态部分由本 ADR 取代；快照单元语义保留并仍被查询/基线/对账引用）。
- hash 对账 API（checksum 表拉取）随 v0.3 phase-4（fallback-freshness）交付；SDK 侧兜底轮询、对账周期与重连策略归 phase-8；phase-3 交付增量流本体。
- SDK 需增量合并逻辑（视图语义 apply）与对账触发全量拉，复杂度略高于快照覆盖，换稳态带宽。
- checksum 计算规则须跨语言稳定（v1.x Rust SDK）：canonical 序列化（instanceId 排序、确定性字段拼接）而非依赖 protobuf 序列化字节，phase-4 定稿。
